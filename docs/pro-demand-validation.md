# TryJS Pro demand-validation test

## Hypothesis

Teachers and technical authors who publish runnable frontend examples will show explicit interest in a paid TryJS option that makes examples durable, private, or custom-branded.

The test is deliberately reversible: one shared toolbar entry on the JS, TypeScript, Web, and React playgrounds; one extra contextual link on `/web` and `/react`; one `/for-teachers` page; a public prefilled GitHub issue; and existing analytics. The page demonstrates the free JavaScript and TypeScript workflow that already exists: create, share, embed, edit, and run. It also states that Web and React support editing and previewing, not sharing or embedding. There is no backend, account system, private lead form, checkout, pricing promise, or unavailable control disguised as working functionality.

## Signals

- Cross-playground workflow interest: `pro_interest` with `source=toolbar` and `intent=educator_workflow`, emitted once per tab session from the toolbar shared by JS, TypeScript, Web, and React.
- Context workflow interest: `pro_interest` with `source=web_preview` and `intent=educator_workflow`, emitted once per tab session on Web and React.
- Landing denominator: `pro_landing_view` with `audience=teachers_authors`, emitted once per tab session.
- Willingness-to-pay CTA intent: `pro_interest` with `source=for_teachers_page` and `intent=willingness_to_pay`, emitted once per tab session even if someone clicks both GitHub feedback links.
- Qualitative evidence: submitted public GitHub issues generated by the feedback link. A click is intent; an issue from a distinct teacher or technical author that describes a workflow and willingness to pay is stronger evidence.

Do not treat page views, CTA impressions, repeat clicks, or a drafted-but-unsubmitted issue as customers or revenue.

## Decision rule

Use a 14-day test window beginning with the production deployment of this correction. Disregard signals collected before that deployment when evaluating this message. Review sooner only if `pro_landing_view` reaches 200 deduplicated tab sessions.

- **Success threshold:** at least 10 deduplicated `willingness_to_pay` CTA sessions, an intent rate of at least 8% of `pro_landing_view` sessions, and submitted issues from at least 3 distinct people that describe a teacher or technical-author use case. Proceed only to customer interviews or a scoped prototype—not billing or a full Pro build.
- **Stop threshold:** after at least 200 `pro_landing_view` sessions, fewer than 3 deduplicated `willingness_to_pay` CTA sessions, an intent rate below 3%, and no submitted issue with a concrete use case. Remove the CTA and page; do not build Pro from this hypothesis.
- **Inconclusive:** anything between those thresholds. Revise the message or audience once and run one more fixed 14-day window. Do not add product infrastructure merely to improve the test.

Report raw counts alongside rates. Calculate the intent rate as deduplicated `source=for_teachers_page`, `intent=willingness_to_pay` sessions divided by `pro_landing_view` sessions. Manually verify distinct issue authors and concrete use cases before calling the qualitative threshold met.
